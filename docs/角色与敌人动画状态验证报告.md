## 二、实现方式

新增 `scripts/art/anim_state.gd`（`class_name AnimState`）——战斗单位动画状态机。

### 优先级
```
death（不可逆终态） > hit > attack（含治疗出手） > move > idle
```

### 输入（全部只读）
| 输入 | 来源 |
|---|---|
| 是否失能 | `CharacterRuntime.is_incapacitated()` |
| 是否消散 | `EnemyRuntime.is_active()` |
| 刚出手 | `total_damage_dealt` / `total_healing_done` 是否增长 |
| 刚受击 | 表现层从 `stage.damage_events` 解析出的本帧标记 |

### 输出
动画名 + 播放进度。一次性动画（attack/hit）按 **progress** 线性取帧（不循环），
循环动画（idle/move/death）按**绝对时间**取帧。

|---|---|---|---|
| `vfx_slash` 近战斩击 | **815** | 敌人被打 + 出手者为 FRONTLINE | 攻击者位置 |

| `vfx_impact` 命中 | **1526** | `damage_events` 每条伤害 | 受击者位置 |
| `vfx_death` 消散 | **509** | `removals` 的 KILLED 记录 | 敌人消散位置 |
| `vfx_deploy` 部署 | **255** | `deploy_character` 成功分支 | 部署格中心 |

**解读**：
- 计数是**每帧累计**（一个持续 0.32~0.70 秒的特效约 20~42 帧），因此数值大是正常的。
- `enemy_anim:move×93884` 远大于其他，符合"敌人始终在推进"的规格。
- 六组特效**全部有真实触发路径与量化证据** —— 本轮指令第四条的要求达成。

### 数据来源的诚实说明
`damage_events` **不携带攻击者信息**（领域层只记录"谁被打"）。因此斩击/箭矢的
出手者归属采用**保守推断**：仅当"敌人被打"时，取距离该敌人最近的、可攻击的
未失能角色，按其 `behavior` 选特效。这是**纯视觉归属**，不参与任何判定；
即便推断错角色，也只是特效位置略偏，不影响伤害、命中或战斗结果。

## 四、可达性检查机制（解决"静默失效"）

### 问题背景
上一轮发生过 **VFX 路径写错导致 6 组特效从未加载**，
而游戏不崩、不报错、stderr 全空 —— 被"安全回退"设计完美掩盖。

### 对策（双通道）
| 通道 | 时机 | 行为 |
|---|---|---|
| **启动校验** `_verify_art_available()` | 战斗场景首次绘制 | 预加载 67 项应存在资源，**缺失即 `GameLog.error`** |
| **运行期追踪** `_track_art_reachability()` | 每帧 | 记录实际绘制过的动画/特效键 |
| **收尾报告** `report_unreachable_art()` | 战斗结算 | 报告"有资源但从未触发"的项 + **正面清单** |

### 生产模式 vs 开发模式
- **生产模式**：资源缺失仍安全降级（回退几何绘制），**不崩溃**。
- **开发/验收模式**：缺失资源**明确报错**，从未触发的动画/特效**明确警告**。

本轮实测启动校验输出：
```
[INFO] BattleScene | 美术资源校验通过：67 项全部存在
```

## 六、如实标注的未达标项

1. **上浮/脉冲动画只有静态证据**：单帧截图能证明发光底衬存在，
   **不能证明上浮过程**。要证明需连续多帧采样，本轮未做。
2. ~~`vfx_slash` / `vfx_heal` / `vfx_death` / `vfx_arrow` 计数为 0~~ —— ✅ **已闭合**。
   本轮把 4 组特效全部接入真实事件（斩击/箭矢由出手事件推断、治疗绑定
   `character_healed`、消散绑定 KILLED），并扩展 autoplay 部署全部三个角色
   （远程与治疗原本永远上不了场，这才是那 4 组特效能触发的前提）。
   实测：`arrow×851 / heal×162 / slash×815 / death×509`。
   **六组特效现均 6/6 有触发路径。**
3. **4K 与 Windows 125%/150% 缩放无真实显示器验收**：
   本机系统 DPI=115（约 120%）。已用**等效逻辑尺寸**（1536×864 / 1280×720）
   在真实窗口中验证，但**这不等同于在 125%/150% DPI 显示器上验收**，
   报告中已标明证据类型。
4. **武器摆动幅度小**（单底图派生策略的代价），本轮未改进。
5. **`char_anim:death` 在部分局中未触发**：该动画只在角色实际失能时播放，
   而 1-1/p1_0_demo 的难度下前排角色往往不会死。这**不是缺陷**，
   而是该局确实没进入该状态 —— 可达性报告会如实标为「本局未进入该状态」。
