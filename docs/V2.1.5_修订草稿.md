## 1.【取代】D 章 · 角色攻击范围与跨线规则

### 1.1 原文（V2.1.4，被取代部分）

- **表 28** 神谷悠真行：「攻击范围：同路线前方 4.0 格以内；**不跨线**。」
- **D-3A / D-13**：攻击范围按「同路线前方 rangeTiles」判定；跨线须由 `maxLaneDelta` 显式限制，
  默认同路攻击 `maxLaneDelta = 0`。

### 1.2 修订后正文（草稿）

**D-3A′（取代 D-3A 中「普通攻击仅限同路线」的默认）**

1. 角色的普通攻击范围由 `attackRange` 显式声明，字段至少含：
   `shape` / `direction` / `rangeTiles` / `maxLaneDelta` / `allowCrossLane` /
   `adjacentLaneRangeTiles` / `targetLimit`。
2. **前线角色（behavior = FRONTLINE）**：普通攻击**只能命中自己所在路线**；
   `maxLaneDelta = 0`、`allowCrossLane = false`。阻挡仍只能作用于本路。
3. **远程角色（behavior = RANGED）**：普通攻击**允许命中自己所在路线及相邻路线**，
   但必须由数据显式声明 `allowCrossLane = true` 且 `maxLaneDelta ≥ 1`。
4. **治疗角色（behavior = HEALER）**：治疗范围沿用曼哈顿距离 + `maxLaneDelta` 的既有规则，
   **不适用**本节的跨线攻击条款。
5. 距离一律以**逻辑格（tile）**计算，**不得**用屏幕像素判定（沿用 V2.1.4 度量 LOCKED 规则）。
6. 攻击方向沿用**面向敌方入口**（`direction = forward`）；角色身后的目标不可攻击。

**表 28′（神谷悠真，取代表 28 的「不跨线」）**

| 属性 | 值 | 性质 |
|---|---|---|
| 本路线前方射程 | 4.0 格 | LOCKED（沿用 V2.1.4 表 28） |
| 相邻路线前方射程 | 3.0 格 | **候选**（第一轮平衡值，需实战验证后定稿） |
| 允许的路线差（maxLaneDelta） | 1 | LOCKED |
| 是否允许跨线（allowCrossLane） | true | LOCKED |

| 阻挡数 | 0 | LOCKED（沿用 V2.1.4 表 28） |

## 2.【新增】D 章 · 远程角色跨路线攻击

### 2.1 正文（草稿）

**D-13A 跨路线攻击规则**

1. 远程角色的普通攻击允许命中自己所在路线及**相邻**路线：
   - 位于**中路**时，可以选择上、中、下三路的合法目标；
   - 位于**上路**时，最多攻击上路和中路；
   - 位于**下路**时，最多攻击下路和中路；
   - **不允许上路角色直接攻击下路**（`laneDelta = 2` 一律拒绝）。
2. 每次普通攻击**仍只选择一个目标**（`targetLimit = 1`）。
3. 跨线**不会**增加攻击频率，也**不会**自动复制攻击次数。
4. 目标优先级继续沿用 **D-11**（① 最接近防守核心 ② 当前正在阻挡 ③ 更早进入攻击范围），
   跨线不改变该优先级。
5. 相邻路线使用独立的射程值（`adjacentLaneRangeTiles`），不得与本路线射程混用。
6. **架构要求**：不得仅通过 `classType` 或 `behavior = RANGED` 让所有远程单位
   无条件获得相同的跨线范围；跨线能力必须逐角色由数据声明。
   声明自相矛盾时（如 `allowCrossLane = true` 但 `maxLaneDelta = 0`）应在构建期**报错**。
7. 本条**只适用于玩家角色**；敌人的攻击范围与跨线限制不受影响。

## 3.【补充】D 章 · Debuff 结算的攻速换算口径

### 3.1 原文（V2.1.4 L556～557，**保持 LOCKED，本草稿不改其文字**）

> 「同一 effectId 的减益不可无限叠层，重复施加默认只刷新持续时间；不同 effectId 的攻击、
> 攻击速度、技能 CD 恢复速度减益以『相对基础值的百分数』先相加，再与增益统一结算，
> 最后夹取下限。有效攻击力、**有效攻击频率**、有效技能冷却恢复速度均不得低于各自基础值的 40%
> （首轮可配置下限）。……控制类沉默仅禁止主动技能，不改变普通攻击频率。」

### 3.2 补充正文（草稿）

**L556 补充：百分数 → 攻击间隔的换算**

1. 规格只定义了「有效攻击频率」的下限，**未明文给出**「攻击速度 ±X%」如何映射到**攻击间隔**。
   本补充条明确该换算口径：

   ```
   effectiveAttackSpeedMultiplier = clamp(1 + Σ攻速百分数, floor, ceiling)
   effectiveInterval              = baseInterval / effectiveAttackSpeedMultiplier
   ```

2. **读法依据**：L556 把 40% 下限明文作用于「**有效攻击频率**」而非「间隔」，
   故频率倒数读法是唯一与规格自洽的读法。
   「间隔 × (1+|Σ|)」的读法会使减益侧与增益侧不对称，破坏「减益与增益统一结算」，**不采用**。
3. 计算顺序：① 不同 `effectId` 的百分数**先相加** → ② 与增益**统一结算** → ③ **夹取上下限** → ④ **换算为间隔**。
4. 无任何攻速效果时，`effectiveInterval` 恒等于 `baseInterval`。
5. 控制类沉默（`category = SILENCE`）**不参与**百分数求和，**不改变**攻击间隔。

### 3.3 上下限的承载

| 项 | 值 | 承载位置 | 性质 |
|---|---|---|---|
| 下限 | 0.4（40%） | `balance.json` → `combat.debuffFloor.attackSpeedPct` | **LOCKED**（L556～557 明文） |
| 上限 | 1.8（+80%） | `balance.json` → `combat.buffCeiling.attackSpeedPct` | **可配置软上限**（表 81，L2113 明标测试基线） |

## 4.【确认 + 补实现口径】H 章 · 首版建议软上限（攻击速度）

### 4.1 原文（V2.1.4 表 81 @ L2105～2113，**保持原文**）

| 属性 | 首版建议 |
|---|---|
| 攻击速度加成 | 局内总增益原则上不超过 +80% |
| 技能冷却缩减 | 原则上不超过 40% |
| 减伤 | 总有效减伤不超过约 60% |
| AP 自然回复增益 | 不超过 +50% |
| 再部署缩减 | 不低于基础时间的 50% |

> 原文附注（L2113）：「以上均为测试基线，不是最终数值。」

### 4.2 补充正文（草稿）

1. 攻击速度的 +80% 上限作用于**攻击频率系数**（与 §3.2 同一口径），即系数上限 **1.8**。
2. 该上限**存于 `balance.json`**（`combat.buffCeiling`），不写死在代码中。
3. **现状如实登记**：当前 Alpha A0.3 构建**无局内强化系统**（属 A0.6），
   因此没有任何攻速增益来源，该上限在现版本**不可达**。
   `combat.buffCeiling.enforced` 应保持 `false`，**不得**宣称该上限已通过实战验收。
4. 递减收益（L2103「同类增益过多时使用递减收益」）属 A0.6 局内构筑范围，本补充条不涉及。
