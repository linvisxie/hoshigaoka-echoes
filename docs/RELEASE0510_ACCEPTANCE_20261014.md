# 0.5.10 完整流程与按钮状态验收

日期：2026-10-14。针对本轮授权的完整流程走查，以及过程中补充的“按钮偶尔变样”截图，进行修复与最终 EXE 实机复验。正式玩家档只在发布时备份、继承；测试使用隔离副本。

## 修复与检查逐项结果

| 项目 | 结果 |
|---|---|
| 用户新增：按钮偶尔变成黑底圆角 | 根因是旧焦点 StyleBoxFlat 带阴影，叠在玻璃按钮上，导致选中时压暗底色且边角不同。全局 Button 焦点改为透明的斜角矢量描边，形状与战斗玻璃按钮相同；透明面板不再产生实心阴影。键盘选中提示保留，原有金色特殊样式保留 |
| 1. 失败、重试、结算与重进 | 在 0.5.9 正式 EXE 实机复现：首次胜利→不看后续剧情→重新挑战→失败→返回校园，会清空上次胜利留下的待看剧情。已修复：失败不创造进度，也不抹掉之前合法获得的待看剧情；失败结算按钮统一写“返回校园”，与实际去向一致 |
| 2. 战斗信息清晰度 | 实测技能、受击与治疗过程中角色血量变化，最终 Boss 战最低观测生命比例约 76%；最终探针丢失伤害反馈事件为 0。保留头顶纯图形血条，不增加血量数字。本轮没有擅自换角色、敌人或技能素材 |
| 3. 难度与策略空间 | 最终 EXE 第十关采用正常 AP、角色属性、时钟及可见操作完成；包含主动撤退与重新部署。没有修改关卡数值。上一轮固定阵型、等级 5/7/9 的 30 次领域模拟保留为参考：不用技能 15 次均失败，使用技能 15 次均胜利；它不证明所有阵容都均衡 |
| 4. 音乐与声音层次 | 核查 10 条战斗配乐的独立文件、有效信号、时长、满幅削波及循环边界。10 条内容不同，没有满幅削波样本。原曲文件全部保留，监考者目标音量为 -11 dB，Boss 三阶段为 -10/-9/-8 dB，普通曲仍为 -12 dB；保留切换淡出、淡入。最终 Boss 战确认三阶段曲均播放，并达到各自目标音量 |
| 5. 全局交互一致性 | 校园与战斗弹窗补上 Tab/方向键焦点循环和 Enter 操作；战斗原有卡片操作仍使用原快捷键。结算默认聚焦继续流程，暂停默认聚焦继续调查。校园弹窗打开时收起背景悬停提示，关闭后恢复。培养按钮未选份数时明确写“升级（先选择份数）”，避免灰色按钮仍显示已选 1 份的误导 |
| 6. 退出告警与稳定性 | 实测正常退出无音频、字体、TextureGL、RID 泄漏告警。仍有 26 个 ObjectDB 实例、16 个 GDScript 资源退出告警；没有将其隐藏或称为全部解决。另做 12 轮包含弹窗、背包、培养、档案、装备和设置的往返检查，结果见随包 stability_report.json |

## 保留与边界

- 不改变已经确认的校园背景、角色立绘、配乐内容与关卡数值。新增素材只有项目内编写的透明焦点矢量边框。
- 本轮覆盖 1280×720 实机与 1672×941 源码视口；没有据此宣称所有非 16:9 窗口、所有硬件和所有输入方式均通过。
- 音频 PCM 检查说明文件完整和有信号，并非人工听感判断，也不保证任意音量组合下的最终混音。循环边界的测量值保存在 audio_report.json，原曲文件没有被重新生成。
- 弹窗开关会刷新当前鼠标的悬停状态，避免已经显示的提示残留；使用 [Godot Viewport 的光标状态刷新接口](https://docs.godotengine.org/en/stable/classes/class_viewport.html#class-viewport-method-update-mouse-cursor-state)。效果以最终 EXE 截图为准。
- 仍需继续打磨不同阵容的长期平衡、完整十关的人工体验，以及残留静态脚本退出告警。本轮没有把这些写成“完美完成”。
- 发布时继承 0.5.9 的最新玩家主档、备份档和设置，正式 AppData 同步备份但不改写。保留 0.5.9 回退版本；试玩 ZIP 不含玩家存档。
